# iPadOS application

This directory contains the native SwiftUI application target. It links the local Rust static library built by `scripts/build-ios.sh`; there is no web server, WebView, or remote renderer in the iPad app.

Read [the implementation status and Mac build guide](../docs/ios/BUILD_AND_STATUS.md) for what is implemented, what's unverified, signing requirements, and physical-device test steps.

The C ABI is declared in `Rust/include/unwritten_studio_core.h`. Keep the ownership rules in sync with `apps/unwritten-studio-core/src/lib.rs` if the boundary changes. The Rust side owns the project/render engine; Swift owns iPad navigation, file/document access, app sandbox paths, and view state.

## Workspace, recovery and Files

The native canvas now matches the usable viewport's aspect ratio in portrait and landscape instead of letterboxing a fixed desktop rectangle. Portrait presents a full-height tabbed panel profile while retaining the saved landscape dock layout. Unmodified built-in landscape workspaces narrower than 1280 logical points, and windows shorter than 600 points, use a composition-first layout with one utility tab group and a full-width timeline, rather than squeezing the viewer between two desktop sidebars. The width-based adaptation leaves custom docks and floating-panel layouts intact. Returning to a larger viewport restores the saved desktop layout; two-finger pan/pinch remains available. Renderer scale is clamped to its 4096-pixel framebuffer limit.

The SwiftUI host uses the full container, then UIKit applies notch/home-indicator insets exactly once. Both logical canvas dimensions and the Retina framebuffer are bounded to 4096 per side so tall portrait windows do not exceed the native renderer's limits. `python3 scripts/test-ios-viewport.py` checks the sizing contract for phone, tablet, split-view and tall viewports on Linux; it does not replace a real UIKit/simulator smoke test.

Save / Output To asks for a filename and then an actual Files **folder before writing or rendering**. The selected directories remain security-scoped for queued outputs during that session. Existing paths require confirmation, and the engine independently refuses render collisions unless the user approves **Replace and Render**. Cancelling does not write a new file. These are folder/path selections, not a promise that rendering succeeded; inspect the render queue status. iOS may require reselecting external/provider folders or relinking media after relaunch.

Dock/workspace preferences are persisted in the app's configuration store. A separate bounded local project checkpoint records edits after roughly 2 seconds and flushes when presentation is paused or the host is destroyed. Reopening restores the local copy **untitled**, never writes the source project, and asks for a new `.unw` when saved. This is recovery, not a replacement for explicit Save: an abrupt OS kill can lose the latest uncheckpointed edits, footage is not embedded, and a corrupt checkpoint is retained rather than overwritten (save a manual `.unw` copy if recovery reports an error). Real iPhone/iPad rotation, Files providers, background termination and signing still need the Mac simulator/physical-device workflow; Linux parser/unit tests cannot certify those behaviours.

Opening a registered project from Files now uses SwiftUI `onOpenURL`, buffers cold/warm handoffs until the workspace is ready, and sends a one-shot `externalProjectPath` to the original frontend's guarded `file.open` command. An outstanding native picker or Save/Cancel decision is not replaced by another handoff. `.aep` always shows **Experimental After Effects Import → Open Copy** first, opens untitled, and must be saved as `.unw`; the source is never overwritten. Security-scoped source access is retained for the session, not permanently. Provider materialization failures are reported; relative media outside the provider grant may still require relinking. Real Files/iCloud handoff on physical iPad remains a device acceptance test, not something Linux regressions certify.

The native experimental `.aep` reader and writer handle only the supported subset; no installed After Effects is required for this route. File → Export → After Effects AEP is separate from native `.unw` Save/Save As. Unsupported text, shapes, effects, masks, 3D, plug-ins and other features may be omitted or rejected. This is not full-fidelity AE compatibility, and generated AEP files have not been validated in AE desktop here. Keep your original project and media. `.aepx` remains unsupported by the native importer. The optional [desktop bridge](../docs/file-format-parity.md#after-effects-desktop-bridge-experimental-partial) still needs AE desktop and exchanges `.unwae`/JSX; it is not required for experimental direct AEP import.
